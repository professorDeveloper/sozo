## Confirmed gaps with user impact

1. **Backup does not cover native extension installations.** BackupService iterates only its six Hive boxes; no native export bridge appears in that service. Android repo metadata is stored separately with `getSharedPreferences("manga")` (`MangaRepoManager.kt:22`), `"aniyomi"` (`AniyomiRepoManager.kt:16`), and `"cloudstream"` (`cloudstream/RepoManager.kt:32`). The service comment promising installed extension repos exceeds the data it exports. Next addition: versioned export/import of repository identifiers, installed source identities and source settings, with a concrete restore coverage report. This is a static coverage finding, not a destructive restore test.
2. **Automatic tracker failures can be invisible and are not queued by the player.** `player_page.history.dart:175–230` explicitly uses a shared once-per-episode ledger, calls trackers fire-and-forget, and swallows failures with `catchError(... => null)`. An offline/outage report can leave playback appearing successful without synchronized progress. Next addition: durable per-tracker pending updates, retry and visible last-sync/recovery status. Service-level behavior should be checked before claiming all retries are absent globally.
3. **“Smart downloads” is only partly present.** Wi-Fi/cooldown/storage controls are real; no followed-title-to-download automation or wall-clock scheduler found. Next addition: opt-in next-episode queue with clear storage/connection policies and user-visible reason for waiting.
4. **Extension support is uneven by platform and language/runtime.** Native ecosystems need Android/bridge; Mangayomi JS runtime excludes Linux and does not mean arbitrary Dart source support. Next addition: surface compatibility and actual source operation health before install, then actionable source error/retry diagnostics. Do not promise universal compatibility.
5. **Single-account data model is not household profiles.** Profile editing/PIN/private lists are present; separate profiles/rating rules are not. Next addition, if family use is a priority: explicit profile-scoped histories/lists/settings, followed by parental policy enforcement.
6. **Film/TV tracking and personal media servers remain distinct missing products.** Trakt and Jellyfin are candidate additions, not small renames of AniList or scraper sources.
7. **Discovery catalogue requires backend connectivity.** `catalog_repository.dart:9–17` intentionally has no app-side cache/fallback. Installed sources and curated repository defaults are separate. Next addition: an explicitly dated last-known catalogue/offline state if offline discovery is a goal.

## Roadmap reconciliation

`docs/ROADMAP.md` is a historical proposal list, not the current feature ledger:

- **Marketplace “user-facing half missing” is stale:** SourceCatalogPage is embedded in SourcesHub and calls the server catalogue.
- **Watch-party chat and reactions “additive” is stale:** both already have concrete service methods/socket events and player integration. Persistent room history remains unconfirmed.
- **Download Wi-Fi-only as future work is stale:** saved settings, queue gating and native flag exist. Cooldown is also implemented; calendar scheduling/automatic new-episode downloads remain unimplemented in the audited paths.
- **Stats existence is correctly acknowledged, but recap data assumptions are too broad:** WatchStatsStore independently accumulates bounded daily/provider totals and stamps its start date. History resume data alone is not a complete historical watch-time ledger. No yearly recap renderer found.
- **Trakt, household profiles and Jellyfin proposals still correspond to absent mobile implementations** in the inspected code.
- Existing dirty appearance/watch-services/genre/backup files mean their current state must not be represented as verified shipped behavior.

## Validation boundaries

Routes and major implementations were inspected, along with targeted test filenames. No test execution or UI/device proof is claimed in this inventory. In particular this audit does not certify source uptime, notifications delivered by the backend, cross-device sync, Chromecast receivers, high-resolution codec support or release distribution. Existing code tests include cast controller/handoff, reader/chapter progress, novel offline/EPUB, tracker matching and player readiness; run the relevant suites and real-device journeys before advertising those guarantees.
